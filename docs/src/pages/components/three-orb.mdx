# ThreeOrb

<Lead>
    ThreeOrb renders the JARVIS orb in WebGL with Three.js, in six visual designs, either as a
    full-screen background layer or inside a container. It ships in its own entry point,
    `jarvis-react-ui/orb`, so Three.js only loads when you use it. For a lightweight CSS version see
    [CssOrb](/components/css-orb).
</Lead>

## Installation

`three` is an optional peer dependency of `jarvis-react-ui`. Install it next to the library when
you use ThreeOrb or `createOrb`:

```bash
npm install three
```

ThreeOrb, `createOrb` and the `OrbEngine` type are not exported from `jarvis-react-ui`; import them
from `jarvis-react-ui/orb`.

## Lazy loading

Load ThreeOrb with `React.lazy` and wrap it in `Suspense`, so Three.js is split into its own chunk
and fetched on first render. Changing `state` makes the particles transition to the new state;
`working` is shown as `thinking`.

<Demo name="three-orb/LazyLoaded" height="tall" align="start" />

```tsx
import { Suspense, lazy } from 'react';

const ThreeOrb = lazy(() => import('jarvis-react-ui/orb').then((m) => ({ default: m.ThreeOrb })));

<Suspense fallback={null}>
    <ThreeOrb state="listening" />
</Suspense>;
```

## Variants

`variant` picks the design. `constellation` (the default) is the original particle cloud; `particle`,
`halo`, `signal`, `reactor` and `lattice` are bloom-lit holographic designs, each loaded as its own
chunk the first time it is used. Try them in the playground: switch the design and the state, drag to
rotate and scroll to zoom, turn on the microphone (processed locally in your browser) or let the demo
cycle through the states.

<Demo name="three-orb/VariantPlayground" height="tall" align="stretch" />

```tsx
<div className="h-96">
    <ThreeOrb state="listening" variant="reactor" fill="container" interactive />
</div>
```

The variant designs know four states. `thinking` and `working` show as `working`, `follow_up` as
`listening`.

## Audio input

Pass a Web Audio `AnalyserNode` as `analyser`, for example from the microphone or from your TTS
playback. In `listening` and `speaking` the variant designs read its level and 16 frequency bands
(80 Hz – 8 kHz) every frame; without an analyser they animate with a simulated voice.
`constellation` reacts to the analyser in every state.

```tsx
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
const ctx = new AudioContext();
const analyser = ctx.createAnalyser();
analyser.fftSize = 1024;
analyser.smoothingTimeConstant = 0.55;
ctx.createMediaStreamSource(stream).connect(analyser);

<ThreeOrb state="listening" variant="lattice" analyser={analyser} />;
```

## Quality and interaction

`quality="low"` renders the variant designs with fewer particles, pixel ratio 1 and half-resolution
bloom, for integrated or mobile GPUs. `interactive` lets the user rotate (drag) and zoom (scroll) the
variant designs; it also makes a `viewport` orb take pointer events, so use it with
`fill="container"` or when nothing has to be clicked behind the orb. Both are ignored by
`constellation`.

## Canvas and layout

With `fill="container"` the orb fills its parent element, which needs a size. With the default
`fill="viewport"` the canvas is `position: fixed` at the top-left corner, sized to the window (it follows window
resizes), sits at `z-index: 0` and ignores the pointer, so it works as a background layer behind
the HUD. Every variant renders on a transparent canvas: only the orb and its glow are drawn, so put
your background color or [GridBackground](/components/grid-background) behind it. In the `orb` slot
of [HUDShell](/components/hud-shell), the shell's grid, stars and horizon stay visible around the
orb. Inside an ancestor with a `transform`, the fixed canvas is positioned relative to that
ancestor instead of the viewport; this demo uses `className="h-full! w-full!"` to fit it into the
demo frame.

## Without React

`createOrb(canvas, options)` drives the same engine on any `<canvas>`. It returns an `OrbEngine`
with the full API, including mock audio and the follow-up ring, which ThreeOrb does not expose:

```ts
import { createOrb } from 'jarvis-react-ui/orb';
import type { OrbEngine } from 'jarvis-react-ui/orb';

const canvas = document.querySelector('canvas');
if (canvas) {
    const orb: OrbEngine = createOrb(canvas, { alpha: true }); // alpha: transparent background

    orb.setState('listening'); // 'idle' | 'listening' | 'thinking' | 'speaking' | 'follow_up'
    orb.setAnalyser(analyserNode); // react to a Web Audio AnalyserNode, or null
    orb.setMockMode('speaking'); // fake audio levels for previews; null turns it off
    orb.setFollowUp(true, 12); // follow-up pulse and countdown ring (seconds left)

    // Later: stop rendering and remove the resize listener.
    orb.destroy();
}
```

The engine renders at window size and listens for window resizes.

The variant designs work the same way with `createVariantOrb(variant, container, { quality })`. It
resolves to an `OrbRenderer` whose canvas fills `container` (a `ResizeObserver` follows its size):

```ts
import { createVariantOrb } from 'jarvis-react-ui/orb';

const orb = await createVariantOrb('halo', container, { quality: 'high' });
orb.setState('speaking'); // 'idle' | 'listening' | 'working' | 'speaking'
orb.onFrame = () => orb.setAudio(level, bands); // per frame: level 0..1, 16 bands 0..1
orb.dispose(); // stop rendering, free GPU resources, remove the canvas
```

## Accessibility

By default the orb is decorative: its root is `aria-hidden="true"` and, unless `interactive`, takes no
pointer events.
Show the assistant's state as text too, for example with a
[StatusLabel](/components/status-label). Pass `aria-label` when the orb itself should be announced;
the root then gets `role="img"` and that label. The orbs do not check `prefers-reduced-motion`; render
a static alternative such as `<CssOrb>` (whose CSS animations stop under reduced motion) when the
user asks for less motion.
