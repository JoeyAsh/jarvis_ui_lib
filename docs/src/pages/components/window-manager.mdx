# WindowManager

<Lead>
    WindowManager lays out a set of windows on a fixed slot grid. Windows dock into slots, can be
    dragged onto other slots to move or swap, and can be undocked into free-floating, resizable
    windows.
</Lead>

<ComponentMeta component="WindowManager" />

## Slot grid

The grid has nine slots: three in the left column (`L1`–`L3`), three in the right column
(`R1`–`R3`) and three in the bottom strip (`B1`–`B3`). The columns are 316px wide, the bottom strip
is 140px high, and the top 60px stay free for a [TopBar](/components/top-bar). The grid is computed
from the size of the WindowManager, which fills its containing block (`position: fixed; inset: 0`):
the viewport, or the nearest ancestor with a `transform`. Column slots share the height left
between the top bar and the bottom strip (at least 60px each), so the 420px demo stages below dock
their windows in the bottom strip.

## Basic

`assignments` maps window ids to slots and is controlled: keep it in state and update it in
`onAssignmentsChange`. Drag a window header onto another slot to move it, or onto an occupied slot to
swap the two windows.

## Compact and expanded

Every window has a mode. `compact` windows are docked in their slot. Click the undock button in the
header, or double-click the header, to switch to `expanded`: the window floats above the grid, larger
than its slot, and can be dragged freely and resized from its edges and corners. The dock button
switches back.

`itemRenderer` receives `{ mode, focused, dragging }`, so a window can show a compact summary while
docked and more detail while expanded.

## Controlled state

`focusedId` and `modes` can be controlled too. Focus moves to a window when it is pressed, dragged or
toggled, and `onFocusChange` receives `null` on a pointer down outside every window. Omit `modes` to
let WindowManager track modes itself; `onModesChange` fires either way.

<Demo name="window-manager/Controlled" height="tall" align="start" />

## Reset

The reset button in each header docks the window, clears any custom size and moves it back to its
home slot. Home slots come from `homeAssignments`; changes to the prop are used by the next reset.
Without `homeAssignments`, the `assignments` of the first render are the home slots.

## Controlled expanded rects

Pass `expandedRects` to own the positions and sizes of expanded windows, e.g. to persist them.
WindowManager then stops storing them and reports every change through `onExpandedRectsChange`:
the default rect when a window is undocked, the final position when a drag ends, each step of a
resize and the removal on reset. Apply the map you receive, otherwise the window snaps back.
`onExpandedRectsChange` also fires when `expandedRects` is omitted.

## Windows

Each entry of `windows` is a `ManagedWindow`:

| Field          | Type                                            | Description                                                   |
| -------------- | ----------------------------------------------- | ------------------------------------------------------------- |
| `id`           | `string`                                        | Unique id; the key in `assignments`, `modes` and `focusedId`. |
| `title`        | `ReactNode`                                     | Header title; also the accessible name of the window region.  |
| `ix`           | `ReactNode`                                     | Index glyph before the title.                                 |
| `badge`        | `ReactNode`                                     | Tag at the right end of the header.                           |
| `itemRenderer` | `(props: PanelContentRenderProps) => ReactNode` | Renders the body; receives `mode`, `focused` and `dragging`.  |

A window without an entry in `assignments` is not rendered.

## Sound

Through the nearest `SfxProvider`, dragging plays `drag_start`, a looping `drag_move` and `drag_end`;
resizing loops `resize`; the undock and dock buttons play `click` plus `expand` or `collapse`, and a
header double-click plays `expand` or `collapse`; the reset button plays `click` plus `recall`. See [Sound effects](/getting-started/sound).

## Accessibility

- Each window is a non-modal `role="region"` named by its `title` through `aria-labelledby`.
- The reset and dock buttons are native buttons with accessible names; the dock button is the
  keyboard equivalent of the header double-click.
- Dragging, swapping and resizing are pointer-only; there are no keyboard shortcuts for them. Offer
  another way to rearrange content (e.g. by updating `assignments`) when keyboard users need it.
