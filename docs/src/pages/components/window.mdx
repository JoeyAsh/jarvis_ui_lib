# Window

<Lead>
    Window is the draggable, resizable panel shell that [WindowManager](/components/window-manager)
    places on its slot grid. Use it directly when you build your own window layout; for the standard
    nine-slot HUD, use WindowManager.
</Lead>

<ComponentMeta component="Window" />

## Basic

A Window is absolutely positioned at `position` (`x`, `y`, `w`, `h` in pixels) inside its nearest
positioned ancestor. The header shows `ix`, `title` and `badge`, and `itemRenderer` renders the
body.

## Compact and expanded

Every window has a `mode`:

- `compact` is the docked state. Resize handles are hidden, and the header shows an **Undock**
  button when you pass `onModeToggle`.
- `expanded` is the free-floating state. The window gets a stronger elevation, the eight edge and
  corner handles become active (when `resizable`), and the header shows a **Dock** button.

Window does not switch modes itself. Clicking the dock/undock button or double-clicking the header
calls `onModeToggle`, and you set the new `mode`. `itemRenderer` receives `{ mode, focused,
dragging }`, so the body can show a compact summary while docked and more detail while expanded.

WindowManager uses the modes like this: a compact window lives in a slot, and dragging its header
moves it to another slot or swaps it with the window there, with
[SnapOverlay](/components/snap-overlay) and [SwapOverlay](/components/swap-overlay) as feedback. An
expanded window floats above the grid at a larger size, can be dragged anywhere and resized, and
the reset button docks it back into its home slot.

## Dragging and resizing

The window never moves itself: `position` is controlled. `onDragMove` and `onResizeMove` report the
pointer offset from the start of the gesture (`dx`, `dy`), and `onResizeMove` also reports the
handle direction (`n`, `se`, ...). Remember the rect when the gesture starts and apply the offset
to it. Drag the header below, undock the window, then drag its edges.

<Demo name="window/DragAndResize" height="tall" />

During a gesture the root element gets `data-state="dragging"` or `"resizing"`. The other values of
`state` (`snap-preview`, `swap-preview`, `settling`, `focused`) are styling hooks for the parent:
`settling` animates position and size changes, and `focused` raises the window above its siblings.
To build drag-and-drop between slots, combine Window with [useSlotDrag](/hooks/use-slot-drag) and
the [slot grid helpers](/utilities/slot-grid).

## Header actions

The reset, dock/undock and close buttons are only rendered when you pass `onReset`, `onModeToggle`
or `onClose`. Pressing them never starts a drag.

## Sound

Through the nearest `SfxProvider`:

- Dragging the header plays `drag_start`, loops `drag_move` and plays `drag_end`.
- Resizing loops `resize` until the pointer is released.
- The reset button plays `click` and `recall`; the dock/undock button plays `click` plus `expand`
  (undock) or `collapse` (dock); the close button plays `click`.
- Hovering the window plays `hover_panel`; hovering a header button plays `hover_button`.

Toggling the mode by double-clicking the header plays no sound. See
[Sound effects](/getting-started/sound).

## Accessibility

- The root is a `role="dialog"` element. It is named by `title` only when the title is a string.
- Window does not move or trap focus and sets no `aria-modal`; it behaves as a non-modal region.
- The header buttons are native buttons named **Reset window**, **Undock window** / **Dock window**
  and **Close window**, so they work with the keyboard.
- Dragging, resizing and the double-click toggle are pointer-only. Offer another way to move or
  resize content when keyboard users need it.
