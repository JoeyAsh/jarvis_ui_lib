# StatusLabel

<Lead>
    A two-line caption for the orb: the current voice state on top and a spaced-out brand mark
    below. Place it under the orb or the [PushToTalkButton](/components/push-to-talk-button).
</Lead>

<ComponentMeta component="StatusLabel" />

## States

`state` takes an `AppOrbState` and maps it to a built-in text. Every state except `idle` is shown
in the bright accent color.

| `state`     | Text           |
| ----------- | -------------- |
| `idle`      | `READY`        |
| `listening` | `listening...` |
| `thinking`  | `thinking...`  |
| `speaking`  | `speaking...`  |
| `follow_up` | `follow-up...` |
| `working`   | `working...`   |

## Custom texts and localization

`labels` overrides the text per state, for example to translate it. It is a partial map: states you
leave out keep their built-in text.

## Custom brand

`brand` replaces the default `J A R V I S` mark. Spaces between the letters are part of the string;
the component only adds letter spacing.

## With the orb state

Feed StatusLabel the same state as your orb and pair it with
[WaveformMeter](/components/waveform-meter)s that run while audio flows. This demo cycles through
the states on a timer; in an app the state comes from your voice pipeline. To switch states by
hand while developing, use [StateSimulator](/components/state-simulator).

## Announce state changes

Set `live` on the one StatusLabel that represents the assistant state. The status text becomes a
polite live region, so screen readers announce each new state after the current speech:

```tsx
<StatusLabel state={state} live />
```

The demos on this page leave `live` off, because the cycling demo would announce a change every
couple of seconds.

## Accessibility

- By default the label is plain text and state changes are not announced. Set `live` to make the
  status text a polite live region (`role="status"`, `aria-live="polite"`), so screen readers
  announce each new state without interrupting. Render only one live StatusLabel per screen, or
  every copy is announced.
- It ignores pointer events (`pointer-events: none`), so it never blocks clicks on the orb behind
  it.
